# AGENTS.md

## Project Overview

`goGenerateCFToken` is a Cobra-based Go CLI for generating Cloudflare API tokens.
Module: `github.com/nicholas-fedor/gogeneratecftoken`, Go 1.27.1.

- Entrypoint: `main.go` → `cmd.Execute()` → `cmd/root.go`
- Commands: `cmd/token/`, `cmd/config/`, `cmd/credentials/`
- Internal logic: `internal/cloudflare/`, `internal/credentials/`, `internal/config/`, `internal/flags/`, `internal/logging/`, `internal/metadata/`
- Aggressively strict linting: 60+ linters enabled via `build/golangci-lint/golangci-lint.yaml`

## Commands

Use `task` (Taskfile.yml), not `make`. There is no Makefile.

- `task setup` — install deps + tools
- `task build` — builds `bin/gogeneratecftoken`
- `task test` — `go test -race -test.fullpath=true -timeout 30s -covermode atomic -v ./...`
- `task test-coverage` — produces `coverage.out`
- `task lint` — `golangci-lint run --fix --config build/golangci-lint/golangci-lint.yaml ./...`
- `task vet` — `go vet ./...`
- `task mock` — regenerates mocks via Mockery v3 (`build/mockery/mockery.yaml`)
- `task docs` — generates CLI docs to `www/content/docs`
- `task docs-serve` — Hugo dev server on `www/`

## Validation Order

Always run `task lint` then `task vet` before tests. Do not use `go build` for validation.

## Code Style

- **Go files use tab indentation** per `.editorconfig` (not spaces), even though the default Go formatter also uses tabs. The extended formatter stack (`gci`, `gofmt`, `gofumpt`, `goimports`, `golines`) is enforced by `task lint`.
- License header is required on every file: `// SPDX-License-Identifier: AGPL-3.0-or-later`
- Package doc comments (`doc.go`) are expected in packages with multiple files.

## Testing

- Table-driven tests with testify (`assert`, `require`, `mock`).
- Mocks are generated by Mockery v3 into `internal/*/mocks/`. Run `task mock` after interface changes.
- **Never manually edit files under `mocks/` directories.** They are auto-generated.
- Tests run with race detector and 30s timeout by default.

## CI

Both GitHub Actions and CircleCI are used:
- GitHub Actions (`.github/workflows/`): tests, lint-go, lint-gh, security, scorecard, release, build, docs, changelog updates. Path-filtered on `cmd/**`, `internal/**`, `tools/**`, `go.mod`, `go.sum`, `main.go`.
- CircleCI (`.circleci/config.yml` → `.circleci/continue-config.yml`): dynamic path-filtered job that continues to run tests when `cmd/`, `internal/`, `main.go`, `go.mod`, or `go.sum` change.

## Docs

CLI documentation is generated (`tools/docgen`) into `www/content/docs/` for a Hugo-based site. Run `task docs` after CLI changes.

## Conventions

- Branch naming: semantic prefixes (`feat/`, `fix/`, `chore/`, `docs/`, `refactor/`, `test/`, `style/`), optionally with issue number (`feat/#1-add-feature`).
- Commits: Conventional Commits (`type(scope): description`).
- PRs: Conventional Commit title, body with `## Changes` section.
